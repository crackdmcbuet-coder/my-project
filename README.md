# স্বপ্নের ব্যাখ্যা (Dream book module)

রোগী নিজের ভাষায় স্বপ্ন লিখলে সিস্টেম **আপনার বই** থেকে মিল থাকা এন্ট্রি খুঁজে হুবহু ব্যাখ্যা দেখায়।
মিল না থাকলে নির্দিষ্ট বার্তা দেখায়: "এই স্বপ্নের ব্যাখ্যা আমাদের বইয়ে পাওয়া যায়নি।"

> এই মডিউলে `data/dreams.sample.json`-এর ব্যাখ্যাগুলো **ভুয়া নমুনা**। আসল বই থেকে `data/dreams.json` তৈরি করলে সিস্টেম সেটাই ব্যবহার করবে।

## মূল নিয়ম: খোঁজো, বানিও না

1. **শর্টলিস্ট:** বইয়ের স্বপ্নের শিরোনামে অক্ষর-গ্রাম (n-gram) অনুসন্ধান। `সাপ` আর `সাপে`-র মতো রূপভেদ মেলে। AI লাগে না।
2. **বাছাই:** Claude শর্টলিস্টের ১০টা এন্ট্রি থেকে বাছে কোনটা সত্যিই মেলে। উত্তর শুধু আইডি-র তালিকা (structured output)। সন্দেহ থাকলে খালি তালিকা।
3. **উত্তর:** ব্যাখ্যা সবসময় ডাটাবেস থেকে আসে। কোডে যাচাই হয় যে আইডিগুলো শর্টলিস্টেরই। মডেল নিজে কিছু লিখলে তা রোগী কখনো দেখে না।
4. মডেল বা API ব্যর্থ হলে (refusal, নেটওয়ার্ক, key নেই) অনুমান না করে "পরে চেষ্টা করুন" দেখায়।

## চালানো

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env            # ANTHROPIC_API_KEY বসান; সার্ভারে export করুন
export ANTHROPIC_API_KEY=...
uvicorn app.main:create_app --factory --port 8000
# ব্রাউজারে http://localhost:8000 (ডেমো পেজ), API: POST /api/dream {"text": "..."}
pytest
```

আপনার নিজের ওয়েবসাইট থেকে `POST /api/dream` কল করুন। API key ব্রাউজারে দেবেন না, শুধু সার্ভারে রাখুন।
আলাদা ডোমেইন হলে `ALLOWED_ORIGINS` সেট করুন; প্রক্সির পেছনে থাকলে `TRUST_FORWARDED_FOR=true`।

## বই থেকে ডেটা তোলা (PDF / DOCX / HTML)

```bash
# ১. ড্রাই-রান: কোনো খরচ নেই, শুধু কতটা লেখা পাঠানো হবে দেখায়
python -m ingest.structure --book data/books/sopner-boi.pdf --title "বইয়ের নাম"

# ২. প্রথম ২ চাঙ্ক চালিয়ে আসল খরচ মাপুন (শেষে টোকেন ও আনুমানিক খরচ ছাপে)
python -m ingest.structure --book data/books/sopner-boi.pdf --title "বইয়ের নাম" --run --limit-chunks 2

# ৩. পুরো বই
python -m ingest.structure --book data/books/sopner-boi.pdf --title "বইয়ের নাম" --run
```

- আউটপুট `data/dreams.generated.json`। এখানে `entries` হলো যেগুলোর `dream` ও `interpretation` বইয়ের লেখার সাথে অক্ষরে অক্ষরে মিলেছে। যেগুলো মেলেনি সেগুলো `needs_review`-এ, নিজে দেখে ঠিক করুন।
- **এটা লাইভ ডেটায় যায় না।** দেখে যাচাই করে যা ঠিক, `{"entries": [...]}` আকারে `data/dreams.json`-এ রাখুন। `keywords` ঘরে সমার্থক শব্দ (যেমন `"সর্প"`) যোগ করলে খোঁজ ভালো হয়।
- স্ক্যান করা (ছবির) PDF-এ টেক্সট থাকে না। স্ক্রিপ্ট তা জানিয়ে থেমে যাবে; আগে OCR লাগবে।

## খরচ

মডেল বদলাতে `ANTHROPIC_MODEL` (ডিফল্ট `claude-opus-5-5`; সস্তা বিকল্প `claude-sonnet-5-5`)।
প্রতি স্বপ্ন-অনুসন্ধানে মডেলকে মাত্র কয়েকশ টোকেন দেওয়া হয়, তাই খরচ খুব কম। প্রতিটা কলের টোকেন সংখ্যা লগে থাকে (স্বপ্নের লেখা লগে যায় না)। প্রতি IP-তে ১০ মিনিটে ২০ বার সীমা আছে (`RATE_LIMIT_*`)।

## সীমাবদ্ধতা (এখনো যা বাকি)

- লাইভ Anthropic API-র সাথে এখনো পরীক্ষা হয়নি। টেস্টগুলো নকল ক্লায়েন্ট দিয়ে চলে। প্রথমে আপনার key দিয়ে ১০-২০টা আসল স্বপ্ন চালিয়ে দেখুন।
- `MIN_SCORE` (ডিফল্ট `0.1`) আসল বইয়ের ডেটা দিয়ে ঠিক করতে হবে। বেশি হলে মিলতে পারা এন্ট্রিও বাদ পড়ে, কম হলে বাছাইয়ে বেশি খরচ হয়।
- একসাথে বহু এলিমেন্টের স্বপ্নে (সাপ + পানি) প্রতিটার আলাদা ব্যাখ্যা দেখায়, সর্বোচ্চ ৩টা। বইয়ে সংমিশ্রণের আলাদা এন্ট্রি থাকলে সেটাই শিরোনামে রাখুন।
- রেট-লিমিটার একটাই প্রসেসে কাজ করে।
- পরের মডিউল: লক্ষণ-ফর্ম, আমল, দুআ মেকার, অডিও/PDF, আয়াত, একই "খোঁজো, বানিও না" কাঠামোতে।
